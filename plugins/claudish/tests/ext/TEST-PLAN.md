# Independent claudish run-status tests

Tests were written from the supplied spec, frozen wire contract, rendering/wake contracts, public state declaration, engine declarations and fake harness only. No implementation was inspected, imported during validation, or executed. ## Assumptions and precedence

1. **Frozen contract wins over old proposals.** Tests use `session_id`, mandatory per-start team `run_id`, ContractMeta list envelopes, exact capabilities and full frames. Activity is a tool name (`Bash`), not the older `Bash: bun test` example. Version negotiation, not a release string, is the compatibility gate.
2. **Monitor decision overrides older immediate-wake prose.** Delegation events and settled-team final units wait ten seconds; unfinished-team slot events do not. Toasts are still immediate. An accepted monitor notification is visible via `wakeLedger`'s public `by: 'monitor'` entry, not counted in `h.submits` (which records the mod only).
3. **The read-verb hook is authoritative for permissions.** It is PreToolUse, not PermissionRequest; cancel is not auto-allowed. The newer published `sending` state also takes precedence over §3.5's old three-state pseudocode: a held permission/cancel answer is not a timed-out answered `sent` request.
4. **Timing uses the supplied deterministic kit.** POLL=1500ms allows a ~1Hz active feed to be observed; grace boundaries use the published ledger's notice `at` plus 10000ms, not an implementation timer or guessed poll phase. Counts are measured after kit dispatch/clock settlement, not real sleeps. The final frame test uses the fake's exported REAP_MS (8s), not a fabricated production reap deadline.
5. **Public state is fair game.** Only documented `wakeLedger`, `state.set` observations and engine pane descriptions are inspected. No implementation constants/functions, hashes or undocumented button keys are imported. UI controls are located by visible model/label and pressed using their discovered keys.
6. **Appending is a kit seam.** `support.append` swallows only the expected bottom rejection after separately proving the exact original event reached the supplied append spy. Test rows simulate main-conversation task-notifications. This is not evidence of a real transcript append or monitor-started turn.
7. **Layout assertions measure descriptions, not paint.** The independent measurer covers numeric widths, Box direction/gap/padding, Button brackets and one-cell ASCII/glyph fixtures. It makes no Unicode-wide/combining glyph claim. Small custom frames are well below any realistic style budget; indexed spans must become hex but no undocumented indexed-palette RGB mapping is hardcoded.
8. **Unsupported capture UI has no prescribed wording.** Tests allow an omitted Show, a no-op unsupported action, or an explicit unavailable tab; they require zero capture calls and no fake live screen. Malformed-capture fallback accepts a waiting/unavailable/capture diagnostic rather than prescribing its prose.
9. **Source paths are HOME-relative by design.** They will not resolve in this sandbox. No test runner, type checker, real server, engine session, or hook subprocess was invoked here.

## Gaps / limitations

- **G1 — Execution/toolchain and artifact boundaries.** The implementation and engine runtime are absent; all 286 tests remain unexecuted against them. No `claude plugin validate`, plugin loading, HOME import resolution or `tsc -p` result is claimed. Manifest packaging, exported state-type completeness, actual hot-reload persistence and the outside-plugin filesystem-write boundary need HOME validation. Only no-process/no-foreign-MCP and no-render-write behaviour are covered here.
- **G2 — Real surfaces, appends and wake turns.** The engine kit checks element descriptions, not terminal/desktop pixels, actual clipping/wrapping, keyboard dispatch or native dock geometry. Its append core is unavailable; unchanged forwarding is checked at the supplied spy only. Real monitor startup/output delivery, exactly one actual idle turn, Desktop's invisible-turn limitation, read-only physical key transport and reload recovery against transcript messages require live checks with the supplied stdio fake. That server was read as a contract harness but not launched.
- **G3 — Engine permission semantics.** Bun subprocess tests prove the classic hook's bytes/exit and registration, not own-plugin re-entry handling, another open dialog's queue, person deny/ask-rule precedence, or actual Stop approval UI. A held/refused cancel is simulated, not a real permission interaction. Bare/safe/untrusted/disabled-hook admission also requires engine integration.
- **G4 — Missing/retained runs and compaction.** The supplied UI contract refers to §3.4 missing/UNKNOWN/LOST deadlines and §3.2 compaction policy without supplying those sections. No deadline is invented. Placeholder rows, synthetic LOST, run retention expiration, server restart recovery, earlier-run summaries and high live-row scrolling are untested.
- **G5 — Reload and extended wake/Stop recovery.** True module respawn, armed-state reset across it, inflight nonce transcript recovery and its explicit at-least-once window are untested. The suite covers 30s/60s refusal retry and parked turn-end retry, but not parked ten-minute timer, independent timer survival after poll shutdown, three bounded guarantee exceptions, thirty-minute running-turn guard, transport-stalled answered cancel's twenty-second watchdog, or epoch races inside an awaited in-flight operation.
- **G6 — Capture edge limits.** Seq=0 boot frames, never-spawned panes, higher-than-server since_seq, malformed individual spans, style-budget/plaintext fallback thresholds, capture retention errors, oversized/Unicode frames, cursor rendering and latest-pane races are not covered. The exact style budget and detailed frame cropping policy are not in the provided contracts. Text/fg/bg/bold, no-spans mode, unchanged frames and final-frame cessation are covered.
- **G7 — Extra source/monitor cases.** No explicit installed-server-to-direct-server probe-failover test; direct origin is tested. Monitor dedupe for AWAITING_PERMISSION (monitor grammar has only needs-input), waited= field matching for a wait already answered, assistant/subagent rows, grammar length ceilings/unknown-field tolerance, absolute or truncated paths, mixed-failure/cancelled team settle mapping, repeated-path monitor-generation races, late-monitor duplicate window and stale cache reload are not exhaustively tested. EMPTY→monitor failed is assumed to be the monitor's failure vocabulary for an unusable terminal answer. Fully malformed list envelopes are tested, but every malformed nested row field/error code is not.
- **G8 — Remaining visual specifics.** Column drop order through activity/tokens/tools/provider/loops is independently checked, along with documented fit widths and glyph-only floor. Every intermediate model/id shrinking step, all metadata dim attributes, alignment across differing provider widths, null age/tools/loops, omitted provider, exact zero-count exclusion and every height-overflow grouping combination are not exhaustively checked.
- **G9 — Prescribed transpilation command fails in this environment.** `bun build --no-bundle <file> --outdir /dev/null` was attempted and failed before transpilation with `ENOTDIR: Not a directory: could not open output directory "/dev/null" (open)` on Bun 1.4.0. `/dev/null` is a device, not an output directory. Equivalent `bun build --no-bundle <file> > /dev/null` succeeds for every written TypeScript file (including the shared helper), without bundling or resolving the intentionally HOME-relative imports. This is syntax/transpilation validation only, not a runtime or typecheck pass. The documented command deviation is environmental, not concealed as a successful exact command.

## Validation record

- All writes stayed under `tests/ext/`; all inspected source/contracts/harness files stayed inside the working directory.
- Every TypeScript file passed the equivalent no-bundle transpilation command above.
- Declaration counts and unique titles were checked with a registration-only recorder: imports were removed from an in-memory copy, `test` only recorded titles, and **no test body was called**. This did not load an implementation or execute a hook.
- No implementation behaviour test was run. See G1–G9 before interpreting coverage as verified feature behaviour.
